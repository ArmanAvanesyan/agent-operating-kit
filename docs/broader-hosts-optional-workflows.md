# Broader hosts and optional workflows

Phase 10 is opt-in. Protocol parsing, static preparation, live route qualification,
platform certification and production activation are separate results. A compiled
registry entry does not establish that a binary is installed, authenticated,
available to an account, isolated or able to execute a task.

## Host registry and evidence

`aok host list --json` reports the compiled descriptor and independent gates.
The registry contains Codex, Claude Code, OpenCode, agy, Cursor, Gemini, OpenClaw,
Hermes Agent and the distinct Codex Cloud route. Task data cannot register an
executable driver. Native-format import/render support remains independent.

Versioned host evidence uses `aok-host-bridge/v2`. Driver identity is a digest of
its compiled descriptor, registry/argument code and protocol normalizer. Preparation binds exact assignment, policy and input
bytes. Runtime admission binds the executable, actual launch, configuration,
profile, account, workspace and host version. P7 checks this binding at its
existing launch boundary after durable intent. P3 still owns reservations and
settlement; P8 still owns acceptance. Host terminal events never establish AOK
acceptance or tracker completion.

The lightweight `aok-host-driver-input/v1` offline driver input envelope is distinct from a captured P6
policy. It contains `version`, `policy` (or `assignment`) and no authority.
New-driver fixture replay takes a manifest with exact host, attempt ID, original
observation time and hash-bound frame assets. Supply `--as-of` and a new output
directory. Repeated frames within an attempt replay are deduplicated. Offline replay does not consume capacity or maintain a cross-manifest ledger.
Credential-bearing event fields are rejected before raw retention. Unknown
controls, tools, context and subscription capacity remain unknown.

```text
aok host list --json
aok host inspect --host opencode --policy driver-policy.json --as-of 2026-10-24T12:00:00Z --out inspect
aok host prepare --host opencode --assignment assignment.json --policy driver-policy.json --as-of 2026-10-24T12:00:00Z --out prepared
aok host replay --host opencode --manifest frames.json --as-of 2026-10-24T12:00:00Z --out replay
```

Discovery without a protected version probe reports installed version unknown.
Qualification reporting does not launch a disposable conformance test or turn
supplied controls into a live qualification. Resume and delegation remain
closed. Cancellation requested is distinct from confirmed process stop.

The additional protocol references are [OpenCode CLI](https://docs.opencode.ai/docs/cli/),
[Cursor output formats](https://cursor.com/docs/cli/headless),
[Gemini headless operation](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/headless.md)
and [OpenClaw agent](https://docs.openclaw.ai/cli/agent). These declarations are
protocol implementation inputs, not evidence for a particular installed route.
agy, Hermes and Codex Cloud retain explicit protocol/control discovery gates.
Codex Cloud cannot inherit local workspace, identity, quota or cancellation
proofs; no local or paid API fallback is available.

## Compatibility and migration

V1 readers retain their interpretation. V2 is an opt-in extension, not a rewrite
of historical signed documents. Migration envelopes retain exact source bytes,
source digests, original observation dates and unresolved obligations; activation
is disabled. Quarantined store snapshots include all SQLite tables, including
methodology projections and provisioning send intents. Replacing a store still
requires quiescence, current protected authority and P9 anti-rollback controls.
Copying records never refreshes evidence or releases a hold or fence.

## Go parity and methodology lifecycle

The Go binary provides methodology listing/scaffolding/artifact validation,
work-item listing/scaffolding/validation and read-only work-system setup through
an injected reader. Go/Python oracle tests compare generated bytes and canonical
JSON reports. The Go implementation does not start Python. Project initialization
and existing Python commands retain their established behavior.

`aok methodology check-transition` inspects a signed
`aok-methodology-lifecycle/v1` request. `record-transition` requires a protected
role-key/evidence service and P7 revision-checked journal append. The distributed
binary installs no such service. FDD, DSDM and AUP reuse their catalog edges,
required artifacts and approval roles. P7 checks an installed methodology
binding at admission, during execution and at acceptance. Replayed approvals,
stale artifacts and revision conflicts block. A selected `.aok` profile grants
no approval. Lifecycle enforcement qualification remains separate from content
availability. AM is optional lightweight guidance; it adds no universal modeling
requirement.

Embedding applications can install explicit services with
`cli.RunWithPhase10Services`; JSON and environment discovery cannot populate
these Go interfaces. The P7 store provides `EnableGovernance` and
`RecordMethodology` for the protected append callback. Enabling a projection
creates no role authority.

## Jira Data Center

`jira` remains Cloud-only. `jira-datacenter` requires `aok-tracker/v2`, API 2,
instance/project identities, pinned server version, base path and TLS trust hash.
The operator read policy must approve the exact deployment and credential
reference. HTTP reads require external `--tls-roots` bytes matching that pin;
redirects and arbitrary injected TLS transports are rejected. No credentials
are captured. [Data Center search](https://developer.atlassian.com/server/jira/platform/rest/v11002/api-group-search)
uses offset pagination independently of Cloud search continuation.

Issue fields, comments, links and transition prerequisites retain source bytes.
Wiki text is preserved and marked lossy for plain-text mapping. Unknown link
semantics are not inferred. Observation fingerprints are not atomic write
preconditions. Packet projection uses explicit mappings; missing or lossy
required fields produce drafts. Workflow bindings use opt-in `aok/v1alpha2` for
Data Center; v1 provider enums remain unchanged. Data Center writes are blocked
until a separately qualified concurrency-safe operation transport exists.

## Provisioning

`aok work-system plan --observation FILE --desired FILE --as-of RFC3339 --out NEW`
creates `aok-work-system-plan/v1`; `validate-plan --plan FILE` checks it offline.
Existing `work-system setup` remains read-only.

Initial changes are additive GitHub Project fields/options or Azure inherited
process fields/states in an existing project/process. System processes,
organization/project/process creation, deletion, conversion, ambiguous names
and destructive replacement block. Desired changes do not manufacture an item
`SyncOperation` or grant.

`apply --plan FILE --change INDEX --out NEW` sends at most one operation and
requires externally installed authority, a durable P7 consumption boundary and
an operation-qualified writer. The default binary emits a blocked report. A
provisioning-specific signed grant binds the exact plan, scope and change, with
current revocation/qualification checks. Before sending, reobserve and reject
drift. Consume the logical operation before sending. A lost response remains
ambiguous and cannot be resent. `reconcile` performs readback only. Readback must
match the requested kind, name, parent and value, with a native immutable ID.
P9's `ActivatedBoundary` adds an external anti-rollback witness to the local
journal. No automatic rollback is attempted.

## Advisory campaigns

`aok campaign plan` consumes explicit requirements, validated PlanDefinitions,
exact source hashes, a frozen evidence policy and a bounded set of permitted
priority variants. It emits `aok-campaign-proposal/v1`. Unknown requirements
remain an abstention. Cycles, unknown dependencies, invalid plans and changed
assets reject. Captured plan/report bytes are bounded and reproducible.

`campaign evaluate` uses P4's signed outcome-shard verification and conservative
cohort estimators. `campaign compare` reuses the actual selector replay under
frozen development/validation data. Only explicitly allowed ranking priorities
may differ; route, quality, billing, capability and permission gates cannot be
changed. Locked audit data cannot be used to optimize. Adoption requires a new
reviewed policy version. Production activation requires an independently
qualified fixed-DAG route. There is no campaign dispatch, dynamic DAG executor,
online learning or automatic policy mutation.

## Qualification and platform limits

See the [Phase 10 delivery matrix](implementation/phase-10-delivery-evidence.md)
and [Windows preservation gate](windows-preservation-probes.md).
Cross-compilation is not Windows certification. Native tests must name exact
Windows build, toolchain, privilege level and local NTFS volume. ARM64, ReFS and
network shares are separate gates. No actual Windows certification, host live
qualification or provider writeback qualification was run while implementing
this offline slice.
