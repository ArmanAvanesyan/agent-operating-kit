### Lightweight modeling

Select this overlay only when a concrete uncertainty or coordination risk makes
a shared model useful. Choose the smallest model that answers the question,
work collaboratively with the people who will use it, and keep it close to the
implementation so it can evolve with the code.

- State the decision or risk the model should clarify before drawing.
- Prefer a short sketch, example, or model note over a comprehensive model.
- Record the model's owner, intended use, and evidence that resolved the need.
- Stop modeling when the decision is clear; do not create a model as a gate by
  itself.
- Revisit or discard the model when it no longer describes the delivered
  system or informs a current decision.

This guidance supplies no lifecycle transition, approval, or acceptance
authority. Such enforcement remains a separate qualification gate.
